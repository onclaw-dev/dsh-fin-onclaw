# Onclaw 数据接口说明

本 Skill 是 Onclaw Harness 插件随包提供的数据接口说明与调用入口。它帮助选择接口、确认参数和注意事项，并通过唯一的 `onclaw_data_interface` 受控桥读取真实数据。

## 使用边界

- 二十四个接口不会分别注册成 Harness Tools；真实读取统一调用 `onclaw_data_interface`，传入规范接口名和参数对象。
- 该桥只接受索引中的二十四个规范接口名，不接受 HTTP path、method、URL、Header、Token 或 SQL。
- 认证由 Harness Host 继承 Onclaw 插件登录状态。不要查找、索取、输出或保存 bearer token；出现 `AUTH_REQUIRED` 时提示用户到 Onclaw 设置页登录。
- 插件前端与 Agent 调用共享同一个 Host Data Runtime、身份域、增量缓存和并发请求合并。
- 本 Skill 不执行完整工作流，也不直接分析原始 Window 长表；大结果应先筛选或形成有界特征。
- 不得把接口名称改写成任意 HTTP path、method 或 SQL 代理。
- 普通与 VIP 账户使用相同的二十四个业务接口、参数、字段、Window/Runtime 控件和公共安全边界；不得按会员层级删减接口、缩小业务参数或臆造 VIP 专属字段。
- 两类账户的差异只限上海交易日时间门禁、请求频率额度和每日请求/响应流量额度。后端判定权威，不得通过切换接口或改写参数绕过。

调用前阅读 [访问控制与额度](references/访问控制与额度.md)。遇到结构化拒绝时保留错误码及可用的 `limit`、`usage`、`reset_at`：额度错误应停止盲目重试并等待重置；交易日门禁不能当成空数据；日历不可用是临时服务状态，不要据此改变业务结论。

## 选择接口

先阅读 [数据接口索引](references/数据接口.md)，按以下领域定位：

- 梯队与涨跌停：竞价、连板、反复、首板、炸板、跌停和个股上下文。
- 业绩：报告期、公告日期、公告明细、业绩溢价 Window，以及时间线中的业绩异动摘要与 T 至 T+3 轻量溢价登记。
- 市场：股票 Window、日线、月线、量价趋势、Runtime、四来源统一时间线和板块情绪。
- 监管：活跃监管、历史监管、监管线、监管线历史，以及时间线中的进入、续监管、停牌、复牌和退出事件。
- 题材：股票题材、题材搜索、题材详情和题材市场信息。
- 美股异动：可用日期和每日异动明细。

确定接口后，只读取索引链接到的 `references/interfaces/<中文接口名>.md`。中文文件标题用于发现，文档内的 `onclaw_*` 规范接口名用于生成接口驱动；不要一次加载全部二十四份参考文档。

需要按事件日期联合分析题材、资讯、业绩异动和监管生命周期时，优先使用 `onclaw_get_market_timeline`：省略来源参数表示四类全选；多选使用 `source_types`；兼容单选使用 `source_type`，二者不能同时传入。业绩与监管条目自带有界摘要和最多四个已成熟溢价观察点，无需再抓取原始行情长表重算。

实现通信解析或 Python 特征输入前，读取 [传输与结构重建](references/传输与结构重建.md)。该文档区分 gzip 传输、顶层/嵌套 TableData、Snapshot 增量表和 Topic 递归树。

## 形成接口驱动

输出接口驱动或流程草案时至少写清：

1. 目标与触发条件。
2. 每个节点使用的规范接口名。
3. 必填参数、参数来源和日期口径。
4. 节点之间传递的标识符或数据范围。
5. 哪些结果必须经过筛选、关联或 Python 特征处理。
6. settled 与 runtime 数据如何区分。
7. 空结果、缺失数据、访问门禁、额度耗尽和部分结果的处理方式。
8. 最终交给 LLM 的应是有界特征或证据，不是未处理的原始长表。

## 文档维护

接口索引和详细参考由 `references/interface-catalog.json` 确定性生成。接口定义变化后，在 `fiagent_frontend` 目录运行：

```bash
node harness/skills/onclaw-data/scripts/generate-interface-docs.mjs
```

使用 `--check` 只校验，不修改文件。
