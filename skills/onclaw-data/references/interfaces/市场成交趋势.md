# 市场成交趋势

> 分组：市场行情
> 状态：通过单一 `onclaw_data_interface` 受控桥调用；不是独立注册的 Harness Tool。

规范接口名：`onclaw_get_market_volume_trends`

调用时令 `interface_name` 等于上述规范接口名，并把下表参数放入 `arguments`。认证由 Onclaw Harness Host 登录会话隐式提供，不得传入 Token、HTTP path、method 或 Header。

普通与 VIP 账户共享本接口的参数、返回字段和公共安全边界；访问判定及额度错误处理见 [访问控制与额度](../访问控制与额度.md)。

## 用途

读取现有市场成交趋势。

读取量价趋势数据，用于成交活跃度、放量和持续性特征。

## 参数

参数对象必须满足 `additionalProperties: false`，只允许下表字段。

| 参数 | 类型 | 必填 | 可选值 | 说明 |
|---|---|---:|---|---|
| `trade_date` | string | 否 | — | YYYY-MM-DD 日期。 |

## 输出与处理

### 验证来源

- 实际请求：HTTP 200。
- 契约来源：实时样本 + MarketDataRepository._row_to_dict + MarketVolumeTrend。
- 已用只读测试请求确认响应外形；字段语义与类型再以服务序列化代码核对。
- 数据库模型只用于核对已下发字段的标量类型和含义；未被 service/module 序列化的列不在本契约中。

### 响应外壳

| 路径 | 类型 | 枚举/固定值 | 说明 |
|---|---|---|---|
| `code` | integer | — | 业务状态码；成功为 `200`。 |
| `msg` | string | — | 业务状态说明。 |
| `data` | 按接口定义 | — | 业务数据。文档下方的路径均以完整响应为起点。 |

业务数据形态：**对象**。

### 返回字段

| 路径 | 类型 | 枚举/固定值 | 说明 |
|---|---|---|---|
| `data.trade_date` | string(date) | — | 请求日期补齐得到的交易日。 |
| `data.source` | string \| null | — | 成交趋势写入来源，实时为 ths_realtime.turnover_minute；KPL market_volume_trends/MarketCapacity 仅作历史补充/非实时。 |
| `data.source_update_time` | string(date-time) \| null | — | 成交趋势源更新时间，实时来源 THS turnover_minute 字段 mtime。 |
| `data.final_minute_time` | string(time) \| null | — | 成交趋势最后一个已发生分时时间，实时来源 THS turnover_minute 最新非空 turnover 点；KPL 历史补充来源 time。 |
| `data.final_volume` | number \| null | — | 当前已发生累计成交额，实时来源 THS turnover_minute header key=turnover；KPL 历史补充来源 volume。 |
| `data.final_pre_volume` | number \| null | — | 昨日成交额/同比参考，实时来源 THS turnover_minute header key=turnover_pre；KPL 历史补充来源 pre_volume。 |
| `data.final_predict_volume` | number \| null | — | 预测全天成交额，实时来源 THS turnover_minute header key=predict_turnover；KPL 历史补充来源 predict_volume。 |
| `data.final_turnover_change` | number \| null | — | 较昨日变动，实时来源 THS turnover_minute header key=turnover_change。 |
| `data.final_percent` | number \| null | — | 兼容字段：KPL 历史补充 market_volume_trends.percent，THS turnover_minute 无对应字段，实时写入为空。 |
| `data.final_tips` | string \| null | — | 兼容字段：KPL 历史补充 market_volume_trends.tips，THS turnover_minute 无对应字段，实时写入为空。 |
| `data.final_tag1` | string \| null | — | 兼容字段：KPL 历史补充 tag1，THS turnover_minute 无对应字段，实时写入为空。 |
| `data.final_tag2` | string \| null | — | 兼容字段：KPL 历史补充 tag2，THS turnover_minute 无对应字段，实时写入为空。 |
| `data.point_count` | integer \| null | — | 当日成交趋势点数量。 |
| `data.volume_points` | string | — | 完整成交趋势曲线包，统一按 THS turnover_minute 点结构保存，金额单位为元；每点仅含 timestamp、time、turnover、turnover_pre、turnover_change，未来分钟 turnover 可为 None，KPL 历史补充按万元源值换算为元后写入同结构。 |



### 结构重建

- 先由 HTTP 客户端处理可能存在的 gzip，再解析 JSON；不要对已经得到的对象再次解压。
- 只在上述明确标为 `TableData` 的路径执行 `columns[i] -> rows[*][i]` 映射。
- Topic 树、分页对象、运行态对象和动态键映射保持原有对象/数组结构，不要递归转换为 DataFrame。
- 完整规则见 [传输与结构重建](../传输与结构重建.md)。

- 建议超时上限：60000 ms；实际调用仍应支持取消。
- 原始长表、Window 或 Runtime 结果应先经过范围裁剪、关联或特征处理，再进入最终 LLM 判断。
- 空结果不自动代表失败，应结合交易日、筛选条件、权限和数据可用性判断。

## 编排建议

1. 在流程中明确该接口的参数来源，而不是让最终判断 LLM 临时猜测参数。
2. 记录日期口径、股票范围、题材或报告期等关键坐标。
3. 将接口结果传给确定性筛选或 Python 特征节点；只把有界证据交给判断节点。
4. 保留数据状态、revision、coverage、warnings 和缺失信息。

## 注意事项

- 明确 settled 与 runtime 口径；大规模行集应先进入特征处理而不是直接交给 LLM。
- 参数对象是闭合的；未声明字段必须视为错误，不能静默转发。
- 返回值保持现有 Onclaw BaseResponse 及接口数据结构，空值、缺失字段和警告不得自行补零。
