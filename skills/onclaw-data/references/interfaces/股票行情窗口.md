# 股票行情窗口

> 分组：市场行情
> 状态：通过单一 `onclaw_data_interface` 受控桥调用；不是独立注册的 Harness Tool。

规范接口名：`onclaw_get_stock_market_window`

调用时令 `interface_name` 等于上述规范接口名，并把下表参数放入 `arguments`。认证由 Onclaw Harness Host 登录会话隐式提供，不得传入 Token、HTTP path、method 或 Header。

普通与 VIP 账户共享本接口的参数、返回字段和公共安全边界；访问判定及额度错误处理见 [访问控制与额度](../访问控制与额度.md)。

## 用途

通过现有 market snapshot Window/Runtime 接口读取 1..200 只显式股票，不执行候选筛选。

对明确且有界的股票代码集合读取市场 Snapshot Window，并按需附加 Runtime 数据。

## 参数

参数对象必须满足 `additionalProperties: false`，只允许下表字段。

| 参数 | 类型 | 必填 | 可选值 | 说明 |
|---|---|---:|---|---|
| `base_date` | string | 是 | — | 现有 snapshot 接口的 base_date，YYYY-MM-DD。 |
| `start_date` | string | 是 | — | 现有 snapshot 接口的 start_date，YYYY-MM-DD。 |
| `end_date` | string | 是 | — | 现有 snapshot 接口的 end_date，YYYY-MM-DD，不早于 start_date。 |
| `trading_dates` | array<string> | 否 | — | 可选权威交易日期，YYYY-MM-DD，1..120 项；提供后可复用 Host 日期切片。 |
| `data_mode` | string | 否 | `settled`、`include_runtime` | settled 只读 Window；include_runtime 额外调用现有 Runtime 接口。 |
| `known_runtime_revision` | integer | 否 | — | 现有 Runtime 接口的非负 revision。 |
| `stock_codes` | array<string> | 是 | — | 必填，规范化去重后 1..200 项。 |

## 输出与处理

### 验证来源

- 实际请求：HTTP 403。
- 契约来源：Harness 组合契约 + market snapshot service + Snapshot v2 module。
- 只读测试请求返回 HTTP 403（认证或统一访问策略阻止取得业务样本）；以下业务结构来自服务、模块及前端消费契约。
- 数据库模型只用于核对已下发字段的标量类型和含义；未被 service/module 序列化的列不在本契约中。

### 响应外壳

| 路径 | 类型 | 枚举/固定值 | 说明 |
|---|---|---|---|
| `code` | integer | — | 业务状态码；成功为 `200`。 |
| `msg` | string | — | 业务状态说明。 |
| `data` | 按接口定义 | — | 业务数据。文档下方的路径均以完整响应为起点。 |

业务数据形态：**Host 组合对象（Window + 可选 Runtime）**。

### 结构重建

- 先由 HTTP 客户端处理可能存在的 gzip，再解析 JSON；不要对已经得到的对象再次解压。
- 只在上述明确标为 `TableData` 的路径执行 `columns[i] -> rows[*][i]` 映射。
- Topic 树、分页对象、运行态对象和动态键映射保持原有对象/数组结构，不要递归转换为 DataFrame。
- 完整规则见 [传输与结构重建](../传输与结构重建.md)。

- 建议超时上限：60000 ms；实际调用仍应支持取消。
- 原始长表、Window 或 Runtime 结果应先经过范围裁剪、关联或特征处理，再进入最终 LLM 判断。
- 空结果不自动代表失败，应结合交易日、筛选条件、权限和数据可用性判断。

## 编排建议

1. 在流程中明确该接口的参数来源，而不是让最终判断 LLM 临时猜测参数。
2. 记录日期口径、股票范围、题材或报告期等关键坐标。
3. 将接口结果传给确定性筛选或 Python 特征节点；只把有界证据交给判断节点。
4. 保留数据状态、revision、coverage、warnings 和缺失信息。

## 注意事项

- 明确 settled 与 runtime 口径；大规模行集应先进入特征处理而不是直接交给 LLM。
- 参数对象是闭合的；未声明字段必须视为错误，不能静默转发。
- 返回值保持现有 Onclaw BaseResponse 及接口数据结构，空值、缺失字段和警告不得自行补零。
