# 业绩溢价窗口

> 分组：业绩与公告
> 状态：通过单一 `onclaw_data_interface` 受控桥调用；不是独立注册的 Harness Tool。

规范接口名：`onclaw_get_performance_premium_window`

调用时令 `interface_name` 等于上述规范接口名，并把下表参数放入 `arguments`。认证由 Onclaw Harness Host 登录会话隐式提供，不得传入 Token、HTTP path、method 或 Header。

普通与 VIP 账户共享本接口的参数、返回字段和公共安全边界；访问判定及额度错误处理见 [访问控制与额度](../访问控制与额度.md)。

## 用途

调用现有 /financial-performance/premium-window，返回后端已经计算的公告 T+n 溢价；Host 不重算公告、交易日或价格。

围绕一个报告期和公告事件日读取业绩事件及 T+n 溢价窗口，适合构造业绩套利或公告效应特征。

## 参数

参数对象必须满足 `additionalProperties: false`，只允许下表字段。

| 参数 | 类型 | 必填 | 可选值 | 说明 |
|---|---|---:|---|---|
| `report` | string | 是 | — | 报告期，例如 2026-02。 |
| `event_date` | string | 是 | — | YYYY-MM-DD。 |
| `forecast_types` | array<string> | 否 | `preview`、`express`、`notice` | 未提供额外说明。 |
| `performance_types` | array<string> | 否 | — | 现有接口动态业务类型，最多 20 项。 |
| `horizons` | array<integer> | 否 | — | 1..21 项，每项为 0..20 的交易日 horizon。 |
| `max_events` | integer | 否 | — | 1..300。 |

### 最小参数骨架

```json
{
  "report": "<report>",
  "event_date": "<event_date>"
}
```

占位符必须在真正实现或 Inspector 测试前替换为符合说明的值；不要把占位符作为真实参数发送。

## 输出与处理

### 验证来源

- 实际请求：HTTP 200。
- 契约来源：实时样本 + FinancialPerformanceModule。
- 已用只读测试请求确认响应外形；字段语义与类型再以服务序列化代码核对。
- 数据库模型只用于核对已下发字段的标量类型和含义；未被 service/module 序列化的列不在本契约中。

### 响应外壳

| 路径 | 类型 | 枚举/固定值 | 说明 |
|---|---|---|---|
| `code` | integer | — | 业务状态码；成功为 `200`。 |
| `msg` | string | — | 业务状态说明。 |
| `data` | 按接口定义 | — | 业务数据。文档下方的路径均以完整响应为起点。 |

业务数据形态：**对象**。

### 返回字段

| 路径 | 类型 | 枚举/固定值 | 说明 |
|---|---|---|---|
| `data.report` | string | — | 规范报告期。 |
| `data.event_date` | string(date) | — | 公告行情事件日。 |
| `data.horizons` | integer[] | — | 已归一化、升序去重的 T+n。 |
| `data.trading_dates` | string(date)[] | — | 从事件日起用于计算的交易日序列。 |
| `data.events` | object[] | — | 逐公告溢价事件。 |
| `data.events[].announcement` | object | — | 公告预览字段，见公告表列。 |
| `data.events[].ts_code` | string | — | 标准股票代码。 |
| `data.events[].base_close` | number \| null | — | T+0 基准收盘价。 |
| `data.events[].premium` | object[] | — | 各 horizon 的价格与溢价。 |
| `data.events[].premium[].horizon` | integer | — | T+n 偏移。 |
| `data.events[].premium[].trade_date` | string(date) \| null | — | 目标交易日。 |
| `data.events[].premium[].close` | number \| null | — | 目标收盘价。 |
| `data.events[].premium[].premium_pct` | number \| null | — | 相对基准收盘价的百分比溢价。 |
| `data.coverage` | object | — | 公告与定价覆盖统计。 |
| `data.coverage.announcement_count` | integer | — | 纳入公告数。 |
| `data.coverage.priced_count` | integer | — | 取得基准价的事件数。 |

### 结构重建

- 先由 HTTP 客户端处理可能存在的 gzip，再解析 JSON；不要对已经得到的对象再次解压。
- 只在上述明确标为 `TableData` 的路径执行 `columns[i] -> rows[*][i]` 映射。
- Topic 树、分页对象、运行态对象和动态键映射保持原有对象/数组结构，不要递归转换为 DataFrame。
- 完整规则见 [传输与结构重建](../传输与结构重建.md)。

- 建议超时上限：60000 ms；实际调用仍应支持取消。
- 原始长表、Window 或 Runtime 结果应先经过范围裁剪、关联或特征处理，再进入最终 LLM 判断。
- 空结果不自动代表失败，应结合交易日、筛选条件、权限和数据可用性判断。

## 编排建议

1. 在流程中明确该接口的参数来源，而不是让最终判断 LLM 临时猜测参数。
2. 记录日期口径、股票范围、题材或报告期等关键坐标。
3. 将接口结果传给确定性筛选或 Python 特征节点；只把有界证据交给判断节点。
4. 保留数据状态、revision、coverage、warnings 和缺失信息。

## 注意事项

- 报告期、公告日和交易日是不同坐标；缺失价格或公告信息不能用零值代替。
- 参数对象是闭合的；未声明字段必须视为错误，不能静默转发。
- 返回值保持现有 Onclaw BaseResponse 及接口数据结构，空值、缺失字段和警告不得自行补零。
